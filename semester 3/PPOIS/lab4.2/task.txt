Задание 2. Графы
Реализовать обобщённый контейнер (в C++ — шаблон класса) в соответствии с выбранным вариантом. Реализованный контейнер должен соответствовать следующим требованиям:

иметь как минимум один параметр обобщённого типа, задающий тип элементов, для хранения которых используется контейнер;
предоставлять публичные псевдонимы/описания используемых типов там, где это принято в выбранном языке (typedef/using — в C++; параметры типов и вложенные типы — в Java и C#; аннотации типов — в Python); полный перечень определяется вариантом задания и разработчиком;
конструктор по умолчанию, создающий пустой контейнер;
конструктор копирования (в языках без явного конструктора копирования — метод глубокого копирования, например Clone/copy/аналогичный статический фабричный метод);
деструктор, если это предусмотрено языком и необходимо для освобождения ресурсов (либо эквивалентный механизм: Dispose/using, try-with-resources, __del__ — если требуется явное освобождение ресурсов помимо сборки мусора);
проверку на пустой контейнер (метод empty/is_empty);
очистку контейнера (метод clear);
операцию присваивания копированием: перегруженный оператор = — в C++; в языках, где такая перегрузка невозможна (Java, C#, Python), — именованный метод копирования состояния (assignFrom/CopyFrom);
операции сравнения: ==, !=, >, <, >=, <= (в виде операторов — в C++ и C#; через equals/Comparable — в Java; через магические методы __eq__, __lt__ и т. д. — в Python);
методы для доступа к элементам контейнера (перечень зависит от варианта задания);
методы для добавления элементов в контейнер (перечень зависит от варианта задания);
методы для удаления элементов из контейнера (перечень зависит от варианта задания);
классы (или объекты) итераторов для перебора элементов и методы для их создания (тип итераторов и перечень методов зависит от варианта задания); используйте идиоматичный для языка механизм итерации — пользовательские итераторы, удовлетворяющие концепции итератора STL, — в C++; интерфейсы Iterator/Iterable — в Java; IEnumerator/IEnumerable и yield — в C#; протокол __iter__/__next__ — в Python;
текстовое представление контейнера, построенное с помощью его итераторов и обобщённого алгоритма обхода (operator<< со std::for_each — в C++; переопределённый toString()/ToString()/__str__, использующий итерацию по контейнеру, — в Java, C#, Python);
выброс исключения при возникновении ошибочной ситуации.
Как и для всех лабораторных работ, здесь обязательны и unit-тесты с покрытием более 90%, и консольное меню, демонстрирующее работу сортировки и контейнера (см. общие требования к тестированию и к CLI-интерфейсу в common_requirements.md).

При защите лабораторной работы студент должен уметь работать с обобщёнными типами выбранного языка, знать структуру и свойства стандартной библиотеки контейнеров этого языка, типы итераторов и способы использования обобщённых алгоритмов и функциональных объектов (функторов/лямбда-выражений /делегатов).

Варианты заданий
Во всех вариантах ниже общие требования — см. раздел «Задание 2» выше. Контейнер не должен раскрывать способ внутреннего представления графа — наружу предоставляются только методы и итераторы. У контейнера должен быть один параметр типа, определяющий тип значения, хранимого в вершине графа.

Каждый вариант должен реализовывать:

проверку присутствия вершины в графе;
проверку присутствия ребра между вершинами графа;
получение количества вершин;
получение количества рёбер;
вычисление степени вершины;
вычисление степени ребра;
добавление вершины;
добавление ребра;
удаление вершины;
удаление ребра;
двунаправленный итератор для перебора вершин;
двунаправленный итератор для перебора рёбер (подсказка: обратите внимание на пару значений, аналогичную std::pair — кортеж/tuple/record в других языках);
двунаправленный итератор для перебора рёбер, инцидентных вершине;
двунаправленный итератор для перебора вершин, смежных вершине;
удаление вершины по итератору на вершину;
удаление ребра по итератору на ребро;
обратные (reverse) модификации для всех итераторов;
константные (только для чтения) модификации для всех итераторов.
Необходимость создания обобщённых классов-обёрток для представления вершин и рёбер — на усмотрение разработчика.

Вариант: Неориентированный граф (структура Вирта). Для перебора смежных вершин дополнительно реализовать однонаправленный (только в одну сторону) итератор.
